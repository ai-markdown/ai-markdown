# ai-markdown

A React markdown renderer built for text that arrives one token at a time.

## What this is

A streamed response can end inside a code fence, formula or reference. Pass the
complete accumulated string on every update; the application owns transport
framing, cancellation and retries.

The engine retains a verified prefix when an append and the grammar permit it,
then parses the remaining tail. Otherwise it falls back to a full parse. The React
adapter can reuse unchanged block plans while custom components still respond to
state and context updates. Document coordination shares references between
independently parsed sections; it does not join syntax split across network packets.

```bash
npm install @ai-markdown/react react@^19 react-dom@^19 katex
```

```tsx
import AIMarkdown from '@ai-markdown/react';
import '@ai-markdown/react/typography/default.css';
import 'katex/dist/katex.min.css';

export function Answer({ text, done }: { text: string; done: boolean }) {
  return <AIMarkdown content={text} streaming={!done} />;
}
```

The typography stylesheet supplies the default presentation; KaTeX CSS is needed
for math. In a React Server Components application, use a client boundary and
import global CSS where your framework permits it. Code highlighting and Mermaid
rendering require Mantine or a custom component.

## Packages

| Package                               | Install it when                                                                                                                  | In this Storybook                                                          |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `@ai-markdown/react`                  | You are rendering markdown in React, with any UI library or none.                                                                | The React catalog.                                                         |
| `@ai-markdown/react-mantine`          | Your app already uses Mantine and you want highlighted code blocks, mermaid diagrams, and automatic color-scheme following.      | The **Integrations / Mantine** branch.                                     |
| `@ai-markdown/engine`                 | You are building a renderer for another framework. It is the parsing engine, with no React in it.                                | Not shown — it has no UI to demonstrate.                                   |
| `@ai-markdown/remark-mark-highlight`  | You want `==highlight==` syntax in some other remark pipeline.                                                                   | Not shown — it is a plugin, not a component.                               |
| `@ai-markdown/code-language-detector` | You want to detect the language of unlabelled code, or map fence language names to Shiki or highlight.js names, without Mantine. | Used by **Integrations / Mantine / Code Blocks**; it has no UI of its own. |

The Mantine package **wraps** the React adapter rather than replacing it: same props, same engine, same
streaming behaviour, plus its own renderers. Its typography and color-scheme defaults differ, and `codeBlock` configures the
added code and diagram renderers. The Mantine stories cover those differences.

React and Vue already depend on core and engine at their release-train version. Renderer consumers install the adapter; authors building a new adapter can use core for coordination and engine for parsing.

The Vue 3.5+ catalog is a separate renderer instance in the composition entry. The core package layer is framework-independent and has no standalone Storybook. Shared examples are drawn from `corpus/documents`; syntax-specific regressions retain dedicated inputs.

## Using the canvas

- **Theme toolbar** (the sun/moon icon) switches the whole preview between light and dark,
  including this docs shell. Stories that pin their own scheme say so.
- **Controls** are narrowed per story to the props that story is about, so the panel stays a
  short list of relevant knobs rather than the whole prop surface. The Playground stories are the
  exception — they expose a broader selection of rendering options.
- **Replay buttons** restart a stream from the beginning. Streaming stories render a settled
  document once the replay finishes, so if you arrived late, press it.
- **React Scan** (the lightning icon) outlines re-renders. One caveat: the outlines only appear
  in the standalone iframe view, so use "Open canvas in new tab" first. It is a
  development aid and is disabled in browser tests and public documentation exports.

## Honest capability notes

Things worth knowing before you adopt this, all of them deliberate:

- **The React adapter does not highlight code.** It emits `<pre><code class="language-ts">` and stops.
  Bundling a highlighter would charge every consumer for a dependency many of them already
  solve differently. Use `@ai-markdown/react-mantine`, or bring your own via a custom `pre`
  component.
- **Mermaid diagrams render in the Mantine package only.** Same reason — mermaid is a large
  dependency, and it does not belong in the base renderer.
- **The React adapter ships one typography variant.** The token surface is large and fully overridable, but
  there is no library of prebuilt looks to pick from.
- **The engine plugin catalog is sealed.** You enable and disable what is in it; you cannot add
  arbitrary remark or rehype plugins through that prop. Content preprocessors and custom
  components are the extension points, and they cover most of what plugins were being used for.
- **Directive syntax (`::: warning`) is not rendered.** Documents containing it parse and render
  cleanly, but the directive blocks come through as ordinary paragraphs.
- **React 19 is the floor.** The library uses native `useId()` and is typed against React 19.

There are also two known accessibility gaps in the shipped defaults, tracked in the repository:
GFM task checkboxes have no accessible name, and the default link colour is 3.55:1 against white
rather than the 4.5:1 WCAG AA asks for. Several stories keep their a11y check in report-only mode
because of them, and each one names the rule in a comment where it does.
